# code-explore

## 执行入口

1. 明确问题、项目根目录和所需结论；先探测结构，再定位符号，不假设分层或跨项目调用关系。
2. 需要分析调用关系、模块关系、跨文件业务链路或修改影响时，加载并遵循 `codegraph` skill；已加载则复用。已知文件的局部分析直接读取。
3. 大范围、可独立并行或输出噪声大的探索，可按问题委托；不要逐文件机械分工。
4. 沿相关符号补齐支持结论的调用点、分支和配置。已获得足够证据即停止，无需转录整份源码。
5. 汇总结论、证据与未决项；跨项目分别取证后关联，不把命名相似当作调用证据。

## 探索范围与安全边界

默认读取任务指定项目根目录内自主维护的源码、配置、SQL、Schema、测试、文档和构建清单。任务明确列出的其他仓库各自作为独立根目录。

默认不读取依赖源码包、归档和二进制产物（如 `.jar`、`.class`、`.so`），包管理器缓存或第三方目录（如 `~/.m2/`、`~/.gradle/caches/`、`node_modules/`、`vendor/`、`.venv/`、`site-packages/`），以及 `target/`、`build/`、`out/`、`dist/` 等编译、生成或反编译产物。以下最小公开签名探索和显式例外除外。

### 外部依赖：仅公开签名

为确认项目实际引用的依赖调用契约，可最小化定位目标公开类型、函数、方法、构造器、字段或导出项：

- 读取公开 API 声明、类型定义、接口、头文件或依赖源码中的签名部分，记录依赖标识、可确认的版本、限定符号名、签名、返回类型及声明来源。
- 找到足以确认契约的签名后停止；不得读取方法体、分析内部实现、反编译，或扩展到无关符号、传递依赖及整个依赖目录。

### 显式例外

用户或调用方要求检查依赖实现、编译后实现或其他超出默认范围的内容时，当前任务须明确以下信息；委托时原样传递有效授权范围：

- 依赖名称及包标识、坐标或模块标识，版本或精确路径。
- 具体问题，以及项目源码和公开契约为何不足以回答。
- 允许操作（如读取指定源码、列出产物内容、检查指定编译后实现）。
- 停止条件（目标符号或文件）；不扩展至无关类型、传递依赖、整个缓存或后续任务。

外部签名和授权实现证据均标记 `[外部依赖证据]`，注明标识、版本、路径或声明来源、获取方式，并与项目源码结论分开。核验结果中的证据路径；丢弃未授权的方法体、反编译或范围扩展内容。

## 委托契约（仅在委托时使用）

使用运行环境提供的委托接口，不假定具体 API。每个任务提供下列内容，不依赖子代理自动继承本技能：

```text
角色：源码分析子代理，直接读取分析指定范围，不得再次委托。
项目根目录与分析范围：{root / files / symbols}
问题：{需要回答的独立问题；按需追加领域维度}
边界：仅项目自主维护内容；项目实际引用的外部依赖仅允许目标公开签名探索，记录依赖标识、版本、限定符号名、签名及声明来源，找到签名即停止，不读取实现、反编译或扩展到无关符号。
输出：结论、调用关系或相关行为、精确证据、未决项；外部证据单独标记。仅附支撑结论所需的最小片段。
外部依赖例外（有授权才填写）：{依赖标识；版本或路径；问题及理由；允许操作；停止条件}
```

互不依赖的任务可并行；调用方合并并核验结果。具体源码探索的叶子代理不递归委托；编排型代理仅在任务允许的嵌套深度内分配独立探索。摘要不足时围绕符号或行号补查，不把子代理用作文件搬运工具。除非用户明确索要原文，否则不返回完整文件、近乎完整的逐行转录或无关大段源码。

## 结果要求

- 先回答问题，再给关键实现与证据；按需要呈现调用关系、参数处理、数据操作、异常或外部调用，不强制填空表。
- 引用格式：`项目或模块.原生符号 @ path/to/file:行-行`；上一条已给出完整位置时，同文件跳转可用 `行 → 行`。
- 区分已证实事实、推断和缺失证据；无法确认版本、实现或跨项目关系时明确说明。
